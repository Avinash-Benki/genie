## 1. Pipeline architecture

Canonical order (order matters for cost — cheap filters first):
raw → text extraction → language ID → URL/domain filtering → heuristic quality filters → fuzzy dedup → model-based quality scoring → PII/toxicity handling → decontamination → tokenize → shuffle/shard → mixture weighting.
Tooling: datatrove, NeMo-Curator (GPU dedup), Dolma toolkit, dedupe with MinHashLSH; everything as resumable, logged, per-stage-auditable jobs with kept/dropped counts and reason codes. Keep 1k-doc random samples of REJECTED data per filter — you will discover over-aggressive filters this way.

## 2. Acquisition & extraction

- Web: CommonCrawl WARC (not WET — extract yourself with trafilatura/resiliparse; boilerplate removal quality is a top-3 quality lever). FineWeb/DCLM-style pipelines are the public reference points.
- Code: GitHub/Software Heritage; license-filter (permissive allowlist), file-level dedup, remove autogenerated/minified (line-length & alnum-ratio heuristics), preserve repo structure metadata for repo-level packing.
- PDFs (papers/books): high-value, extraction-hard; use Nougat/marker/olmOCR-class models for math-heavy; keep layout signals.
- LangID: fastText lid.176 threshold ~0.65; per-language pipelines downstream.

## 3. Quality filtering

Two layers:
- **Heuristics (Gopher/C4 rules):** doc length bounds, mean word length 3–10, symbol ratio, bullet/ellipsis line ratios, "lorem ipsum"/curly-brace density, stopword presence, repetition ratios (dup 2–4-gram fraction thresholds). Cheap, kills the worst 20–40%.
- **Model-based:** fastText/linear classifiers trained on "good vs random" seeds (DCLM approach: instruction-like + high-vote content as positives) or small-LM educational-value scorers (FineWeb-Edu style, score ≥3/5 keep). Model filters beat perplexity filters; perplexity-vs-Wikipedia biases toward encyclopedic monotony.
Calibrate per source; keep-rate curves + downstream 1B-scale ablations for any filter change ≥5% of tokens.

## 4. Deduplication

- Exact: sha1 on normalized text (URL-level + doc-level).
- Fuzzy: MinHash (shingle 5-grams, ~9k permutations→bands r×b tuned for Jaccard ~0.8) + LSH clustering; keep one per cluster (prefer longest/highest-score). Suffix-array substring dedup (50+ token repeats) for boilerplate.
- Level: paragraph-level for web, file-level for code, chapter for books. Cross-source dedup last (wiki quotes everywhere).
- Effects: dedup improves quality AND reduces memorization/regurgitation; near-dup survivors act as implicit upsampling — decide intentionally (bounded duplication of top-quality docs can be a feature).

## 5. Decontamination

Remove benchmark leakage from TRAINING data: n-gram overlap (13-grams standard) against all eval sets you'll ever report + fuzzy match on questions AND answers; log hit-rate per eval per source (report it — reviewers ask). Note: n-gram misses paraphrase contamination; for high-stakes claims add embedding-similarity pass on eval questions.

## 6. PII, toxicity, licensing

- PII: regex+NER pass (emails, phones, gov IDs, keys/secrets — secrets scanning on code is mandatory); redact-with-token or drop. Log rates.
- Toxicity: classifier thresholding; keep some borderline (over-scrubbing harms robustness & refusal calibration); never train on CSAM-adjacent — use hash-list filtering (PhotoDNA-class lists for images, NCMEC-style URL lists).
- Licensing: per-source license ledger; code by SPDX allowlist; honor robots/opt-out lists (ai.txt/noai) per policy; keep provenance metadata per document (source, url, timestamp, license) — you cannot retrofit provenance.

## 7. Tokenizers

- BPE (tiktoken/HF tokenizers), byte-fallback mandatory; NFC normalize; digits: individual-digit or 3-digit-group tokens materially help arithmetic; preserve whitespace runs for code (indent tokens).
- Vocab sizing: ~32k mono, 100k–256k multilingual; measure **fertility** (tokens/word) per language — >2× English fertility = that language is undertrained & 2× more expensive to serve.
- Train on the FINAL mixture proportions (tokenizer trained on English-only handicaps everything else permanently). Never change tokenizer mid-run; changing at CPT requires embedding surgery (init new-token embeds from subword means) + expect a loss cliff that recovers.

## 8. Synthetic data generation

Generator patterns:
- **Self-Instruct / Evol-Instruct:** seed tasks → LLM generates instructions + responses; evolve for complexity (add constraints, deepen, broaden).
- **Persona-driven scaling (Persona Hub style):** condition generation on millions of personas → diversity without prompt-set collapse.
- **Textbook-style (phi-approach):** topic taxonomy → generate pedagogical passages/exercises; excellent tokens-per-quality for small models.
- **Backtranslation / instruction-inversion:** high-quality raw docs → generate the instruction that the doc answers (cheap, grounded, low-hallucination).
- **Verified synthesis:** generate → execute/verify (unit tests for code, sympy for math, tool traces replayed) → keep only verified; this is the highest-value class (used for reasoning data at scale).
Quality control: dedup against itself (synthetic collapses to modes), judge-score + heuristic filters, decontaminate against evals (generators leak benchmarks!), track generator model & prompt version per sample. Risks: model-collapse from recursive training on own unfiltered outputs — always anchor with real data & verification; diversity metrics (distinct n-grams, embedding dispersion) on every batch. License note: respect generator ToS for downstream use.

## 9. Post-training data creation

- SFT: capability taxonomy first (coding, math, extraction, writing, multiturn, tool-use, refusals, identity...) → per-cell quotas; response quality bar via multi-judge + human spot-check (≥5% audit); length/format diversity deliberately engineered; multiturn: include user-corrections, interruptions, tool errors.
- Preference pairs: sample K=4–16 from CURRENT policy at temp ~0.8–1.0 → rank via judge ensemble or verifiers → build (chosen, rejected) with margin threshold; avoid pairs where both bad; balance categories; anti-length-bias: length-matched pair subsets.
- Human data: use for (a) judge calibration sets, (b) frontier-hard cases where judges fail, (c) safety edge cases; annotator agreement (Krippendorff α ≥0.6 target), gold-question QC, adjudication tier.

## 10. Data ops

- Version everything: dataset = manifest (shard hashes + pipeline commit + config); training refers to manifest ID; reproducible mixtures.
- Mixture ablations: 1B-scale proxy runs with fixed eval suite; hill-climb weights (or DoReMi-style learned weights).
- Metrics ledger per release: token counts per source/language, dedup rates, filter keep-rates, contamination report, PII report. This document is what saves you in audits and postmortems.
